# C++ 综合考核：简化版机器人裁判系统

## 一、任务背景

参考 RoboMaster 机器人比赛的角色设定，实现一个控制台模拟裁判系统。系统负责登记不同类型的机器人、处理比赛事件、维护生命值并输出最终状态。

本题所有生命值、补给量及状态规则仅为参考内容，相比实际规则并不相同。

## 二、机器人与规则

机器人具有编号、名称、阵营、当前生命值和最大生命值。阵营分为红方、蓝方。编号是整个系统中的唯一标识，即红蓝双方也不能使用相同编号；名称可以重复(不让重复也行)，但不能为空。

| 类型 | 类名 | 初始／最大生命值 | 单次地面补给 |
| --- | --- | --- | --- |
| 步兵 | `Infantry` | 100 | 恢复 20 点 |
| 英雄 | `Hero` | 150 | 恢复 30 点 |
| 哨兵 | `Sentry` | 120 | 恢复 10 点 |
| 空中机器人 | `AerialRobot` | 80 | 不支持，报告错误 |

所有机器人初始满血。机器人受到伤害后，生命值最低为 0；生命值为 0 时视为退场。本题没有复活机制。

补给不能超过最大生命值，输出实际恢复量。例如步兵生命值为 85 时补给，只恢复 15 点。满血机器人补给仍视为成功，但实际恢复量为 0。空中机器人即使满血，地面补给也应失败。

## 三、结构要求

### 1. 结构体与枚举

使用 `Team` 枚举表示阵营，使用 `RobotInfo` 结构体保存编号、名称与阵营。

使用 `EventType` 枚举表示伤害和补给事件，使用如下结构体保存事件：

```cpp
enum class EventType { Damage, Supply };

struct MatchEvent {
    EventType type;
    int robotId;
    int value;
};
```

伤害事件的 `value` 表示伤害值，必须大于 0；补给事件忽略 `value`，测试数据统一填写 0。事件只描述裁判确认后的状态变化，不要求实现攻击方、命中检测或运动仿真。

### 2. 类、继承和多态

设计抽象基类 `Robot`，并实现四个派生类。基类至少提供以下接口：

```cpp
Robot(RobotInfo info, int maxHp);
virtual ~Robot() = default;

const RobotInfo& info() const;
int hp() const;
int maxHp() const;
bool isAlive() const;
int takeDamage(int damage);

virtual int supply() = 0;
virtual std::string typeName() const = 0;
```

`takeDamage` 返回实际扣除量；`supply` 返回实际恢复量，失败时抛出异常。将生命值等状态设为私有成员；派生类可以通过受保护的 `recover(int amount)` 和 `requireAlive()` 等辅助函数复用规则。

裁判系统必须通过基类指针调用 `supply()`，由派生类决定补给效果。不得在裁判系统里按机器人类型写分支来决定恢复量。

### 3. 指针与所有权

用 `std::vector<std::unique_ptr<Robot>>` 保存机器人。使用 `std::make_unique` 创建机器人，将所有权交给裁判系统。不得手动管理这些机器人的 `new` 和 `delete`。

裁判系统至少提供：

```cpp
void registerRobot(std::unique_ptr<Robot> robot);
Robot* findRobot(int id);
int processEvent(const MatchEvent& event);
std::size_t successfulEvents() const;
void printStatus() const;
```

`findRobot` 找不到时返回 `nullptr`；返回的指针只用于访问，调用者不能释放它。`processEvent` 返回事件实际扣除或恢复的生命值。

### 4. 异常处理

以下操作必须失败，且不能改变已登记机器人的状态，也不能增加成功事件数：

- 登记空指针、重复编号或基础信息非法的机器人。
- 操作不存在的机器人。
- 伤害值小于或等于 0。
- 对已退场机器人执行伤害或补给操作。
- 给空中机器人执行地面补给。
- 处理未知的事件类型。

非法参数使用 `std::invalid_argument`，不允许的状态操作使用 `std::logic_error`。如果多个条件同时不合法，可以报告其中一个符合规则的错误，不要求统一检查顺序。

在主函数的循环中捕获 `const std::exception&`，输出失败原因，再继续处理下一条事件。满血的有效地面补给事件计为成功。

依次登记以下机器人：

| 编号 | 名称 | 阵营 | 类型 |

| 1 | 王八 | 红方 | 步兵 |
| 2 | 英雄 | 红方 | 英雄 |
| 3 | 过洞 | 蓝方 | 哨兵 |
| 4 | 无人机 | 蓝方 | 空中机器人 |

随后尝试登记编号为 1、名称为“重复编号”的蓝方步兵，检查其是否失败且原机器人是否保留。

按顺序处理下列事件：

```cpp
const std::vector<MatchEvent> events = {
    {EventType::Damage, 1, 35},
    {EventType::Damage, 2, 50},
    {EventType::Supply, 1, 0},
    {EventType::Supply, 2, 0},
    {EventType::Supply, 4, 0},
    {EventType::Damage, 3, 200},
    {EventType::Supply, 3, 0},
    {EventType::Damage, 99, 10},
    {EventType::Damage, 1, -5},
    {EventType::Supply, 1, 0},
    {EventType::Supply, 1, 0}
};
```

事件 3：机器人 1 接收补给 -> 成功，实际恢复 20 点，生命值：85/100
